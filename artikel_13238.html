How LLMs Actually Work: Tokens, Context and Sampling

Tanggal: 2026-11-03

Hello! After some months (well, almost two years, to be honest 😅) I'm back to writing, this time about something I've been learning: LLMs, automation with n8n, and RAG.

The idea is to present some concepts from the beginning, and then show you two projects I've been working on where I apply these concepts.

I hope you enjoy this new series as much as I'm enjoying writing it.

LLM means ✨Large Language Model✨ It's a computer program trained to understand and generate text.

It's different from a conventional system (a computer one) because it doesn't have written rules. There's no if (question === "...") anywhere, it learned by reading a large amount of text

Pre-training. During training, the model reads a massive amount of text and "plays a game" where it tries to predict the next token. Each time, it compares its guess with the real answer and measures how wrong it was. Then, an algorithm called backpropagation is used to measure how much each parameter contributed to the error, and those parameters are updated so the model gets a better answer next time.

To explain it better, it's like having a panel with a lot of controls, where each combination of those controls gives us a different answer. At the beginning, the answers are wrong, but every time we adjust the controls, they get a little closer to the right one. The algorithm helps us detect which controls we need to change to get a better answer. Then we repeat that over and over, billions of times, until the controls are set the right way.

Post-training. Once the first part of the training is done, the model knows a lot, but it only knows how to continue text, not how to answer you. So we keep training it, now with examples of "good" conversations and with human feedback: people read the model's answers and rate which ones are better.

I'm sure you've seen those job posts where you "help" train AI models. That's exactly this part.

This is the first step. Since the model doesn't read text, your text has to be transformed into tokens (a list of numbers) before being processed. That's tokenization.

What is a token? It's a piece of text. The tokenizer divides the text into parts and assigns a unique number to each one. For example, with the GPT-2 tokenizer:

Note: Those numbers are always the same for the same tokenizer, and they map each piece of text to a specific number.

The context window is everything the model can "see" when it generates a response. It's its working memory, and it has a limit measured in tokens.

This is where the "thinking" happens. This analysis has 2 main parts.

1. Attention Each token looks at the other tokens in the context and decides which ones are relevant to understanding its own meaning.

Same token, different meaning, and attention is the mechanism that figures out which one it is. It means that the model assigns a weight to every other token: high weight for the ones that matter, low weight for the rest.

2. Feed-forward network After attention, each token goes through a neuronal network whose has the memory of the model (not the mmemory of the conversation, otherwise the memoty with the billions of parameter that we mentined at the beginning) and applies the learned patterns to reforce the interpretations more probables and descart tge improbables.

The Transformer has processed all the tokens and now has a list of probabilities for what the next token could be:

Sampling is the mechanism that takes this list and decides which token to use. There are a lot of ways to make this decision, and they are controlled by parameters. Once the parameters are set (depending on the API), the next token is selected.

Once a token is chosen, it's added to the context, and the whole process runs again to predict the next one. The model doesn't write the answer all at once: it generates it token by token, which is why you see responses appear word by word in a chat.

The loop stops when the model generates a special end token or when it reaches the maximum number of tokens allowed. Then the IDs are converted back to text (detokenization), and that's what you see on screen.
